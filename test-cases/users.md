# Тест-кейсы для api/users

## Базовые данные
- **Документация:** `https://restapi.tech`
- **Эндпоинт:** `/users`
- **Headers:** `Accept: application/json`

---

## GET /api/users

### TC-13: Базовый GET /users
- **Параметры:** нет
- **Ожидаемый статус:** 200
- **Обязательные поля в ответе:**
  - `meta.total` (integer)
  - `data` (array)
  - В каждом объекте: `user_id` (integer), `last_name` (string)

### TC-14: Параметр limit
- **Параметры:** `limit=5`
- **Ожидаемый статус:** 200
- **Ожидаемый результат:** `meta.limit == 5`, длина `data` ≤ 5

### TC-15: Параметр offset
- **Параметры:** `offset=2`
- **Ожидаемый статус:** 200
- **Ожидаемый результат:** `meta.offset == 2`

### TC-16: Невалидный limit
- **Параметры:** `limit=abc`
- **Ожидаемый статус:** 422
- **Ожидаемый результат:** `detail` массив с ошибкой

---

## POST /api/users

### TC-17: Создание пользователя с валидными данными
- **Тело запроса:** `{"first_name": "string", "last_name": "string", "company_id": 0}`
- **Ожидаемый статус:** 201
- **Обязательные поля в ответе:** `user_id`, `last_name`
- **Дополнительно:** `last_name` в ответе совпадает с данными созданного пользователя

### TC-18: Создание без обязательного поля last_name
- **Тело запроса:** `{"first_name": "string", "company_id": 0}`
- **Ожидаемый статус:** 422
- **Ожидаемый результат:** `detail` массив с ошибкой

### TC-19: Создание с несуществующей компанией
- **Тело запроса:** `{"first_name": "string", "last_name": "string", "company_id": 9999`
- **Ожидаемый статус:** 404
- **Ожидаемый результат:** `detail.reason`

### TC-20: Создание с неактивной компанией
- **Тело запроса:** `{"first_name": "string", "last_name": "string", "company_id": id_компании_со_статусом_CLOSED}`
- **Ожидаемый статус:** 400
- **Ожидаемый результат:** `detail.reason`

---

## GET /api/users/{user_id}

### TC-21: Получение юзера по ID
- **Параметры:** `user_id={id}` (integer)
- **Ожидаемый статус:** 200
- **Обязательные поля в ответе:** `user_id` (integer), `last_name` (string)
- **Дополнительно:** `last_name` в ответе совпадает с данными созданного пользователя

### TC-22: Получение юзера по несуществующему ID
- **Параметры:** `user_id={<несуществующий_id>}` (integer)
- **Ожидаемый статус:** 404
- **Обязательные поля в ответе:** `detail.reason`

### TC-23: Получение юзера по невалидному ID
- **Параметры:** `user_id=abc` (string)
- **Ожидаемый статус:** 422
- **Обязательные поля в ответе:** `detail` массив с ошибкой

---

## PUT /api/users/{user_id}

### TC-24: Изменение существующего юзера по ID
- **Параметры:** `user_id={id}` (integer)
- **Тело запроса:** `{"first_name": "string", "last_name": "string", "company_id": 0}`
- **Ожидаемый статус:** 200
- **Обязательные поля в ответе:** `user_id` (integer), `last_name` (string)
- **Дополнительно:** `last_name` в ответе совпадает с данными в теле запроса

### TC-25: Изменение существующего юзера без обязательного поля last_name
- **Параметры:** `user_id={id}` (integer)
- **Тело запроса:** `{"first_name": "string", "company_id": 0}`
- **Ожидаемый статус:** 422
- **Ожидаемый результат:** `detail` массив с ошибкой
- **Дополнительно:** в `detail[0].loc` должно быть `"last_name"`, в `detail[0].msg` — `"required"`

### TC-26: Изменение существующего юзера с несуществующей компанией
- **Параметры:** `user_id={id}` (integer)
- **Тело запроса:** `{"first_name": "string", "last_name": "string", "company_id": 9999`
- **Ожидаемый статус:** 404
- **Ожидаемый результат:** `detail.reason`

### TC-27: Изменение существующего юзера с неактивной компанией
- **Параметры:** `user_id={id}` (integer)
- **Тело запроса:** `{"first_name": "string", "last_name": "string", "company_id": <id_компании_со_статусом_CLOSED>}`
- **Ожидаемый статус:** 400
- **Ожидаемый результат:** `detail.reason`

---

## DELETE /api/users/{user_id}

### TC-28: Удаление существующего пользователя
- **Параметры:** `user_id={id}` (integer)
- **Ожидаемый статус:** 202
- **Дополнительно:** после удаления GET /users/{id} → 404

### TC-29: Удаление несуществующего пользователя
- **Параметры:** `user_id=851987` (integer)
- **Ожидаемый статус:** 404
- **Ожидаемый результат:** `detail.reason` содержит `"851987"`

### TC-30: Повторное удаление одного и того же пользователя
- **Параметры:** `user_id={id}` (integer)
- **Ожидаемый статус:** первое удаление → 202, второе → 404
- **Ожидаемый результат:** при втором удалении `detail.reason` содержит ID

### TC-31: Удаление с невалидным ID
- **Параметры:** `user_id=abc`
- **Ожидаемый статус:** 422
- **Ожидаемый результат:** `detail` массив с ошибкой
- **Дополнительно:** в `detail[0].loc` должно быть `"user_id"`, в `detail[0].msg` — `"integer"`
